# 略读卡（skim card）

目标：对一篇论文做**有纪律的略读**，产出一张可追溯的略读卡，用于判断"精读/保留/排除"。

## Route the request

1. 确认论文身份：`read_pdf` 获取页数与元数据，明确 PDF 路径与来源。
2. 确定阅读范围：略读标题、摘要、引言、方法概览、主要结果、局限和结论；定位核心方法/实验所需页面。**明确标注实际覆盖的页段**，不得暗示全文覆盖。
3. 若论文在个人库且已有略读卡（`search_literature_corpus` / `manage_literature_memory`），先复用，除非明确要求刷新。
4. 精读用 `list_paper_assets` + `extract_pdf_region` 核验关键图表；结论标注来源（页码/图表）。

## Execute

回答 5 个问题（每问都要回到原文）：

1. **它解决什么具体问题？** —— 问题、场景、威胁模型与适用边界是否清楚。
2. **现有方法为什么不够？** —— 它声称的 gap 是否成立？现有方法在哪类条件/场景下失效？
3. **它提出了什么核心机制？** —— 区分"概念创新"与"工程组合"；作者声称的 novelty 也可能是换模型、换数据或扩大规模。
4. **哪个实验最直接支持该机制？** —— 找最直接检验该机制的那个实验；检查 baseline 是否公平、指标是否测量目标。
5. **它留下了什么边界？** —— 未覆盖的条件、未排除的解释、讨论里承认的局限。

输出简短阅读卡（表格或行内格式）：

```
问题 | research gap | 核心创新 | 关键证据 | 主要局限 | 精读/保留/排除
```

- **精读**：核心机制有价值且证据链基本成立，值得深入
- **保留**：相关但暂不深入，留作背景/相关工作
- **排除**：不相关或证据不足，记录理由即可

## 证据纪律

- gap 和创新点**必须回到原文确认**——摘要和 AI 回答只能帮助发现，不能作为 claim 证据。
- 引用图表/数据时标注 [论文] + 页码 + 图表编号；工具失败或页面未覆盖要披露。
- 作者未报告的内容写"未公开"，不补全。

## Handoff

汇报：

- 论文身份（路径/页数/来源）与本次实际阅读页段；
- 5 问的答案（每问标注证据位置）；
- 略读卡一行式输出 + 处置建议（精读/保留/排除）；
- 证据缺口：未核实的图表、未覆盖的页面、来源失败。
