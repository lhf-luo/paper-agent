# 略读卡五问法（skim-card 子文档）

供 SKILL.md 的 Execute 阶段按需加载的详细方法。

## 一、5 个问题逐问拆解

### 1. 它解决什么具体问题？

- 一句话复述研究对象、场景、威胁模型；
- 问题是否真实（不是为用某个模型而制造）；
- 适用边界：什么条件/输入下成立。

### 2. 现有方法为什么不够？

- 找出它声称的 gap 对应的**现有方法**；
- 判断 gap 是否成立：现有方法在什么具体场景失败（数据规模、状态空间、泛化、成本…）；
- 若 gap 站不住（只是"没人做过"或"换了个数据集"），明确标注。

### 3. 它提出了什么核心机制？

| 类型 | 判断 |
| --- | --- |
| 概念/机制创新 | 改变了问题定义、观测信号、假设或系统边界 → 高价值 |
| 工程组合 | 换 backbone、拼模块、加 loss、扩数据 → 通常是增量，不构成强创新 |

警惕：**作者声称的 novelty 也可能是换模型、换数据或扩大规模**——要在原文（方法章节）核实"机制层面"的差异，而不是只看摘要的话术。

### 4. 哪个实验最直接支持该机制？

- 找**最直接检验核心机制**的实验（可能是某个消融或某个针对性对比），不是最强的那个；
- 检查：数据是否代表真实场景、baseline 是否公平、预算是否一致、指标是否测量目标、数字是否带单位/误差/条件；
- 若机制没有直接实验支持，记入"证据缺口"。

### 5. 它留下了什么边界？

- Discussion 里承认的局限；
- 未覆盖的条件（如只测了特定协议/数据集）；
- 未排除的替代解释（如没有消融的组件是否真的必要）。

## 二、处置决策标准

| 决策 | 条件 |
| --- | --- |
| **精读** | 核心机制有价值 + 证据链基本成立 + 与你的研究问题相关 |
| **保留** | 相关但暂不深入（背景/相关工作/未来可能用） |
| **排除** | 不相关，或机制/证据明显不足（记录理由，可追溯） |

处置只做初判：顶会/高影响期刊只提升阅读优先级，**不能代替相关性判断**。

## 三、与个人库的衔接

- 略读卡写入研究工作的 skim-card 记录（human 或 ai-assisted，AI 初稿需人工复核）；
- 处置建议同步到个人库 screening 状态（include/exclude/maybe），保持两处一致；
- 已在库中且有有效略读卡的论文，不要重复生成。
