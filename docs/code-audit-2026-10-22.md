# 模块审查与历史兼容清理

审查日期：2026-10-22。范围是本地应用、网页、Agent 工具、存储、画布、论文材料、Wiki 和独立团队服务。按用户要求移除已确认的历史兼容实现；不为不兼容数据建立备份。保留当前功能、远端协议和故障恢复。

## 结果

最明确的问题是废弃格式仍贯穿启动、存储和画布操作，两个旧模块只剩测试引用，以及画布模块的循环依赖。相关代码已清理。静态入口检查当前未再发现孤立的整个源文件，但这不能证明每个导出和每个分支都有业务调用。

后续最值得处理的是大型网页组件和通过多层继承拆分的应用服务。工具没有发现同名注册，部分能力有相近入口，需要按用途整合，不能仅凭名称相似删除。

## 工具重叠的判断

| 工具组合 | 实际差别 | 判断 |
| --- | --- | --- |
| `search_literature` / `collect_literature` | 前者是单查询、少量结果的快速入口；后者支持多查询、提供商、翻页和采集策略。两者共用 `collectLiterature`。 | 有入口重叠，未发现两套检索引擎。未来可将前者收敛为明确预设，须同时更新 Skills 和调用方。 |
| `export_bibtex` / `manage_literature_corpus(action=export, format=bibtex)` | 前者有 DOI 内容协商及来源反馈；后者属于语料导出流程，支持多种格式。 | 值得统一 BibTeX 生成／文件导出约定；本轮没有删除正在使用的入口。 |
| `search_literature_corpus` / `get_personal_library_paper` | 本地筛选列表与单篇身份解析、资源详情。 | 职责不同，保留。 |
| `save_literature_selection` / `import_literature_corpus` | 搜索候选入库与本地 PDF、BibTeX、JSON 导入。 | 来源和校验流程不同，保留。 |
| `read_mineru_material` / `read_pdf` | 结构化正文取证与原始 PDF 定点核验。 | 属于分层阅读，保留。 |
| `update_literature_sidebar` / `edit_literature_sidebar` | 生成／更新展示结果与按修订编辑结构化字段。 | 不是同一操作，需继续明确使用条件。 |

完整工具列表及当前用途见 [Agent 工具清单](agent-tools.md)。MCP 工具由连接服务动态提供，不计入上述 49 个通用扩展工具。

## 尚未重构的结构性问题

1. **网页组件过大。** `canvas-page.tsx` 约 4,700 行、`team-page.tsx` 约 3,400 行、`agent-page.tsx` 和 `library-page.tsx` 各约 2,700 行。菜单、草稿、选择、会话和持久化聚集在页面内，修改影响范围偏大。应按实际交互职责提取 hook 与组件，逐步验证，避免一次重写。
2. **通过继承拆文件。** `PaperAgentApplication`、`WebAgentService`、`PersonalCorpusDatabase`、`LiteratureStore` 都使用较长继承链。中间层依赖共享状态，业务边界不够清晰。建议后续将库、研究、团队和任务协调改为组合服务；本轮没有对这些核心链路做大规模替换。
3. **导出和检索工具的选择成本。** 当前实现已共享部分底层逻辑，但 Agent 仍需理解多个相近入口。应先建立统一的参数、返回值和调用准则，再收敛工具，不宜直接合并所有相近名称。
